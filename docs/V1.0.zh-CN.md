# go-exec V1.0（授权运维/演练）- 产品与工程建议

本文给出一个建议的 “V1.0 最终形态”，前提是：

- 使用场景：仅用于已授权的远程运维、已授权的安全演练。
- 集成形态：既要支持 CLI 直接使用，也要支持作为 Go 库被上层（例如 `vm_ops`）嵌入编排调用。

非目标：

- 不增加主要面向未授权访问、隐蔽化或横向移动的能力。
- 不以扩展协议/执行通道/方法数量为目标，优先把可靠性、可审计性和安全护栏做扎实。

## V1.0 北极星

把 go-exec 做成 “库优先 + CLI 薄封装” 的执行框架：

- `pkg/` 提供稳定的类型化 API 与结构化结果。
- `cmd/` 只负责 UX：flags/config 解析、输出格式化、审计落盘。
- 每次执行都产出机器可读、可审计的结果，并对错误进行一致分类，便于上层自动化处理。

## V1.0 必做交付（P0）

### 1. 稳定的 Go API 契约（便于嵌入）

在 `pkg/goexec` 下定义一个小而稳定的调用契约，供上层编排：

- `ExecutionRequest`
- `ExecutionResult`
- `ErrorKind`（错误分类）

要求：

- `ExecutionRequest` 覆盖：目标、认证、模块/方法选择、命令/参数、超时、输出抓取策略、清理策略。
- `ExecutionResult` 覆盖：目标标识、模块/方法、耗时与元数据、远端产物路径（如有）、输出抓取结果、清理结果（含错误）。
- `ErrorKind` 必须稳定，便于 `vm_ops` 做重试、分流、报表归因。

实现约束：

- 各模块的具体实现仍放在 `pkg/goexec/{wmi,dcom,scmr,tsch}`。
- CLI 相关逻辑不要侵入模块实现（模块不读 flags、不做 stdout/stderr 输出决策）。

### 2. CLI 结果契约（机器可读）

把 “日志” 与 “结果” 分离：

- 日志沿用现状（`--json`, `--log-file`, `--debug`, `--quiet`）。
- 新增结果输出：
  - `--json-result` 或 `--result-file` 输出单次结构化 `ExecutionResult`（未来可扩展 JSONL）。
  - 结果字段必须稳定；如需破坏性变更，要走版本化策略。

### 3. 统一超时模型

当前已有 `--out-timeout`，V1.0 建议统一成完整超时面：

- `--timeout`（整次执行超时）
- `--connect-timeout`（网络连接/会话建立超时）
- `--out-timeout`（输出抓取超时）
- `--out-poll-interval`（输出轮询间隔）
  - `pkg/goexec/context.go` 已有 `ContextOptionOutputPollInterval`，需要在 CLI 暴露并贯穿到 provider。

### 4. 参数校验一致性（降低误用）

所有 “会执行命令” 的子命令行为保持一致：

- 强制 `--exec` 与 `--command` “二选一且互斥”（适用的命令都要做到）。
- 必填项要真正必填，错误提示可理解、可定位。

示例需要补齐的点：

- `cmd/wmi.go`: `wmi proc` 已注册执行 flags，但未强制 `exec/command` 的必选规则。

### 5. 默认安全护栏（面向授权运维/演练）

避免误操作带来的破坏性影响：

- `--dry-run`：打印最终会执行的请求概要（以及结果骨架），不触发执行。
- 对会修改远端状态的操作，要求显式确认：
  - 例如 `--confirm` 才允许改服务/改任务定义等。
- `--audit file`：把每次执行的 request + result 以 JSON 形式独立落盘，便于审计与回溯。

### 6. 修复随机串的确定性问题

`internal/util/util.go` 使用 `math/rand` 但未 seed，导致跨进程启动序列一致，可能引发名称冲突或可预测性问题。

要求：

- 生成的 service/task/hostname 等标识不应在不同启动间重复序列。
- 优先使用 `crypto/rand` 或 UUID 派生短串来保证唯一性与不可预测性。

## V1.0 工程基线

### 测试策略

以 “契约与不变量” 为核心：

- CLI flags 校验测试（必填、互斥、默认值）。
- `Request -> Result` 结构稳定性测试（可用 golden JSON）。
- Cleaner 的 LIFO 清理顺序与错误聚合行为保持不变。

### CI 建议

现有 CI 已在 Linux/Windows 跑 `go test ./...`。可选增强：

- 增加 `go vet ./...`
- 增加不依赖真实远端目标的契约类测试（所有 OS 都可跑）。

## V1.1+（可选，高收益）

### 输出抓取可靠性

在不增加新执行通道的前提下提升输出抓取确定性：

- 避免 “文件刚出现就读取” 导致拿到半截输出。
- 引入可选的完成判定（稳定窗口、终止标记、元数据等）。

### 配置优先（Config-First）

新增 `--config`（YAML/JSON），让 CLI 与库共用同一份配置结构：

- 合并优先级建议：config + env + flags（flags 覆盖）。
- 提供 `--print-effective-config` 便于排障。

### 供应链与发布规范（内部发版）

- SemVer 与变更日志纪律。
- SBOM 与可复现构建说明（结合现有 `.goreleaser.yaml`）。

## 建议的落点（文件）

- Go 契约类型：`pkg/goexec/`（新增文件）
- flags 校验一致性：`cmd/*.go`（例如 `cmd/wmi.go`）
- 超时 flags：`cmd/args.go`, `cmd/root.go`, `pkg/goexec/context.go`
- 审计/结果输出：`cmd/root.go`（以及一个小的 result emitter 工具）
- 随机串修复：`internal/util/util.go`
